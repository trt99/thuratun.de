Why my IT background helps

I’m an IT administrator as well as a tester, so I know how systems, networks and access work. When a test fails, I can often tell whether it’s a bug in the software, a configuration issue or an environment problem. That saves your developers time.

How a testing project runs

The same four steps every time, so you always know where things stand.

  1. UnderstandWe agree on what the software should do and what matters most.
  2. TestI work through the plan and explore beyond it.
  3. ReportYou get findings ranked by severity, each one reproducible.
  4. RetestI verify the fixes before the release goes out.
